## Design note: how the abort is fixed

**The defect.** `inverse_ok` has three acceptance paths. Path 1 is exact
equality with `mutate(tag, base)`. Path 2 accepts a hyphen the canonical
spelling does not have, by stripping it from the surface and comparing. Path 3
accepts a case difference in the inserted material by comparing lowercased,
provided the base letters survive. The ten aborting cells need paths 2 and 3
*at the same time*: an all-caps stem makes `_caps_aware` uppercase the inserted
marker (`eclipse("APP")` is `nAPP`, which becomes `NAPP`), so path 2's
comparison against `"n" + "APP"` fails on the marker's case, and path 3 fails
because the hyphen means the two lowercased strings are still not equal. The
matrix shows the shape is exactly one thing: a vowel-prefixing marker
(`n`, `t`, `h`), a hyphen, and an ALL-CAPS stem. Marker case does not matter.
It is not specific to the four forms found in the corpus.

**The mechanism chosen: generation enumerates its legal realisations and
`inverse_ok` checks membership.** The alternative was to have each reading
carry the surface realisation of its marker, which would mean widening the
`(tag, base)` pair that every caller destructures, and the brief forbids
changing that shape. Membership keeps `(tag, base)` exactly as it is, keeps
the tag inventory, and leaves `mutate()` alone, so every generation caller
still gets strict Caighdeán and only the self-check's notion of "could this
have produced that" widens. The change is one new function plus a rewritten
`inverse_ok`; `demutate` is not touched, so no reading is added or removed.

**Scope.** Realisations are enumerated only where analysis already accepts
them: the bare marker as generation spells it, its uppercase form when the
stem is ALL-CAPS, and a following hyphen only for `n`/`t`/`h` before a vowel.
Lenition is left alone, because path 3 already handles the all-caps `BHEAN`
case and lenition has no hyphen variant.

**Sibling inconsistency found, and deliberately not changed.** `n-APP`,
`N-APP`, `t-APP`, `T-APP` and `h-APP` all get a reading, but `H-APP` does not:
the hyphen-variant branch in `_demutate_core` tests `w[0] == pre` against a
lowercase `pre`, so an uppercase `H` fails it, while `N` and `T` survive via
the separate ALL-CAPS track. Making `H-` behave like `N-` would mean creating
a reading for a string that previously had none, which the brief rules out
except by explicit decision. It is recorded here and left as it is; it is an
odd spelling and nothing in the corpus produces it.
